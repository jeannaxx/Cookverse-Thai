# SiamCulinaryXR — Current Project Context

เอกสารนี้เป็นข้อมูลอ้างอิงหลักของโปรเจกต์ โดยอัปเดตตามคำแนะนำล่าสุดจากอาจารย์ หากข้อมูลในบทสนทนาหรือแผนเก่าขัดกับเอกสารนี้ ให้ยึดเอกสารนี้ก่อน

## 1. แนวทางหลักของโปรเจกต์

SiamCulinaryXR เป็นระบบจำลองการเรียนรู้การทำอาหารไทยผ่านแว่น VR พัฒนาด้วย Unity XR โดยเน้นให้ผู้เล่นลงมือทำจริงในโลกเสมือน ตั้งแต่รับภารกิจ เลือกและเก็บวัตถุดิบ เตรียมอาหาร ปรุง จัดจาน เสิร์ฟ และรับผลประเมิน

โปรเจกต์เริ่มต้นเป็น XR Project ได้เลย เพราะเป้าหมายหลักคือการใช้งานผ่าน VR และต้องพัฒนาระบบเคลื่อนที่ การจับ การวาง และการโต้ตอบแบบ XR ตั้งแต่ต้น การใช้ XR Interaction Simulator ช่วยจำลองการควบคุมบนคอมระหว่างพัฒนาได้ แต่ไม่ถือว่าแทนการทดสอบด้วยแว่น VR จริงหรือ WebXR ได้ทั้งหมด จึงต้องมีการทดสอบกับอุปกรณ์จริงเป็นระยะ

## 2. ขอบเขตตามคำแนะนำล่าสุดของอาจารย์

### ภาคเรียนนี้

เน้นสองส่วนหลัก:

1. ระบบ VR/XR ใน Unity ต้องทำงานได้จริง
2. ทดสอบแนวทางนำระบบไปใช้งานผ่าน WebXR

เป้าหมายคือทำระบบตั้งแต่ต้นจนจบให้เล่นได้จริงก่อน โดยใช้โมเดลทรงง่ายหรือ Blockout ได้ ไม่ต้องรอโมเดลสวย ตัวอย่างเช่น กุ้งสามารถใช้กล่องสี่เหลี่ยมแทน และเมื่อหั่นแล้วเปลี่ยนเป็นบล็อกเล็กหลายชิ้นได้ จุดสำคัญคือระบบต้องตรวจจับการหยิบ วาง หั่น เปลี่ยนสถานะ และลำดับการทำงานได้ถูกต้อง

ช่วงตั้งแต่เริ่มพัฒนาจนถึงต้นเดือนพฤศจิกายน ให้เน้นระบบต่อไปนี้:

- การเคลื่อนที่และการควบคุมใน XR
- การหยิบ วาง ปล่อย และใช้งานวัตถุ
- การรับภารกิจและแสดงเป้าหมาย
- การเลือกและเก็บวัตถุดิบ
- การเปิดตู้เย็นและหยิบวัตถุดิบ
- การล้างและหั่นวัตถุดิบ
- การใช้เตา กระทะ และอุปกรณ์ครัว
- ระดับไฟ เวลา และสถานะอาหาร เช่น ดิบ กำลังสุก สุก และไหม้
- การใส่วัตถุดิบหรือเครื่องปรุงตามลำดับ
- การจัดจาน จุดเสิร์ฟ และจบภารกิจ
- Training Mode ที่แนะนำผู้เล่นทีละขั้น
- Challenge Mode ที่ให้ผู้เล่นจำและทำเอง
- การคำนวณคะแนนและแสดงข้อผิดพลาด
- การบันทึก Action Log เพื่อให้ระบบกฎและ AI ประเมินความถูกต้อง
- การใช้ AI วิเคราะห์ผลและสร้างคำแนะนำหลังจบภารกิจ
- การทดลอง Build และใช้งานผ่าน WebXR
- การทดสอบระบบตั้งแต่เริ่มภารกิจจนถึงผลลัพธ์หลังเสิร์ฟ

### ภาคเรียนที่ 2 ช่วงเดือนมกราคม

- เริ่มพัฒนา WebBoard สำหรับอาจารย์และผู้ดูแลระบบ
- ปรับโมเดล วัตถุดิบ บ้าน สวน และครัวให้สวยงามขึ้น
- ทำ Material, Texture, แสง, Animation, เสียง และรายละเอียดบรรยากาศ
- ปรับ UI และประสบการณ์ใช้งานให้สมบูรณ์
- เพิ่มรายละเอียดและขัดเกลาระบบหลังจากวงจรการเล่นหลักเสถียรแล้ว

การทำโมเดลสวยงามในช่วงเดือนมกราคมยังทัน เพราะภาคเรียนนี้จะมีระบบที่ใช้งานได้จริงและมี Blockout รองรับอยู่แล้ว การเปลี่ยนทรงง่ายเป็นโมเดลจริงควรทำผ่าน Prefab และรักษา Collider, จุดจับ และ Component เดิมไว้ เพื่อลดการรื้อระบบ

## 3. สิ่งที่ตัดออกจากขอบเขตภาคเรียนนี้

WebBoard ถูกเลื่อนไปทำในภาคเรียนที่ 2 ช่วงเดือนมกราคม ตามคำแนะนำของอาจารย์ จึงยังไม่ต้องทำหน้า Dashboard ของอาจารย์หรือ Admin ในช่วงนี้

แผนปัจจุบันคือ:

```text
ภาคเรียนนี้: Unity XR/VR + Gameplay Systems + WebXR
ภาคเรียนที่ 2: WebBoard + Visual Polish + Content Polish
```

หากจำเป็นต้องเก็บผลการเล่นเพื่อทดสอบระบบในภาคเรียนนี้ สามารถบันทึกข้อมูลขั้นต่ำภายในเกมหรือไฟล์ทดสอบก่อนได้ โดยยังไม่ต้องสร้าง WebBoard เต็มรูปแบบ

## 4. Gameplay Flow หลัก

```text
เริ่มระบบ
→ เลือกเมนู
→ เลือก Training หรือ Challenge
→ รับภารกิจ
→ ไปสวนและเก็บวัตถุดิบ
→ กลับบ้านและหยิบวัตถุดิบจากตู้เย็น
→ ล้างและหั่นวัตถุดิบ
→ เตรียมอุปกรณ์และตั้งระดับไฟ
→ ปรุงตามลำดับ
→ จัดจาน
→ นำไปวางที่จุดเสิร์ฟ
→ ตรวจความถูกต้อง
→ แสดงคะแนนและข้อผิดพลาด
```

เมนูตัวอย่างหลักที่เคยวางแผนไว้คือผัดกะเพราไก่ ส่วนกุ้งเป็นตัวอย่างของการทำระบบหั่นด้วยโมเดลทรงง่าย จำนวนและรายการเมนูจริงต้องยืนยันกับอาจารย์ก่อนขยายระบบ

### ผังบ้านและสวนที่ตัดสินใจล่าสุด

แบบร่างล่าสุดบันทึกไว้ที่:

- `Docs/Planning/Environment/Cookverse_TopDown_Layout_Garden_v2.png`
- `Docs/Planning/Environment/SPACE_LAYOUT_GARDEN_PLAN.md`

ข้อตกลงปัจจุบันคือบ้านเป็นเรือนไทยชนบทขนาดเล็กผสมอุปกรณ์ครัวโมเดิร์น ใช้โครงสร้างบ้านยกพื้น ชานบ้าน และหลังคาจั่วแบบ Blockout ก่อน ตัดห้องนอนแบบห้องปิดออก และเปลี่ยนพื้นที่เดิมเป็นมุมนั่งเล่น/ตำราอาหารแบบเปิด

ผู้เล่นเกิดบนชานบ้าน หันไปเห็นจุดรับภารกิจ และมีทางเดินกลางที่ไม่ถูกโต๊ะเตรียมหรืออุปกรณ์ขวาง จากนั้นเดินไปสวนข้างบ้านและกลับเข้าครัวได้โดยไม่เปลี่ยน Scene

สวนวัตถุดิบแบ่งเป็นสี่ส่วน:

- กะเพราและพริกเป็นวัตถุดิบที่ต้องหยิบและเชื่อมกับระบบภารกิจในรอบแรก
- ตะไคร้และมะกรูดใช้สร้างบรรยากาศสวนครัวไทยก่อน ยังไม่ต้องมีระบบโต้ตอบ
- กระเทียมเก็บในตะกร้าบริเวณโต๊ะเตรียม ไม่ทำเป็นแปลงปลูกในต้นแบบนี้

M5 รับผิดชอบบ้าน หลังคา ชาน ทางเดิน แปลงสวน และพืชแบบ Blockout ใน `MainVR.unity` ส่วน M1 รับผิดชอบ Prefab กะเพรา/พริก, `ingredientId` และระบบเก็บวัตถุดิบ หาก M1 รับงานไม่ไหว M5 สามารถช่วยทำ Prefab หรือระบบโต้ตอบได้ แต่ต้องใช้ข้อมูลและ Event ชุดเดียวกันก่อนรวมงาน

ผังนี้เป็นแนวทางสำหรับสร้าง Blockout เท่านั้น ยังไม่ได้สร้างลง Scene และยังไม่ผ่านการทดสอบบน Quest 3 ขนาดและตำแหน่งต้องปรับหลังทดลองแว่นจริง

## 5. การแบ่งงานล่าสุดสำหรับ Mac M5 และ Mac M1

ทั้งสองเครื่องใช้ Unity Project เดียวกัน แต่ควรแยก Scene, Prefab และไฟล์งานให้ชัด เพื่อลดปัญหาแก้ไฟล์เดียวกันพร้อมกัน

### Mac M5 — XR, Integration และ WebXR

Branch ที่รับผิดชอบ: `feature/xr-webxr-integration`

- ดูแล Main XR Scene และ XR Rig
- ระบบเคลื่อนที่ หมุน Teleport และการควบคุมมือ
- ระบบ Grab, Drop และ Interaction กลาง
- เชื่อมระบบภารกิจ วัตถุดิบ การทำอาหาร และคะแนนเข้าด้วยกัน
- ดูแล Cooking State เช่น ระดับไฟ เวลา การคน และสถานะสุก/ไหม้
- รวม Training Mode และ Challenge Mode ให้เล่นครบวงจร
- เชื่อม Action Log, ระบบกฎ และบริการ AI เข้ากับ Gameplay หลัก
- ทดลอง Build สำหรับ WebXR
- ทดสอบประสิทธิภาพและการทำงานบนแว่น VR จริง
- แก้ปัญหาระหว่างระบบและดูแลฉากสำหรับเดโม

### Mac M1 — Gameplay Modules, UI และ Test Content

Branch ที่รับผิดชอบ: `feature/gameplay-content-ui`

- สร้าง Blockout บ้าน สวน ครัว และตำแหน่งอุปกรณ์
- สร้าง Prefab ทรงง่ายสำหรับวัตถุดิบ มีด เขียง ตู้เย็น กระทะ จาน และจุดเสิร์ฟ
- ทำระบบย่อยใน Scene ทดสอบ เช่น เก็บวัตถุดิบ เปิดตู้เย็น ล้าง และหั่น
- ทำ Objective UI, Tutorial Prompt, Checklist และ Result UI
- เตรียมข้อมูลสูตร ลำดับขั้นตอน เงื่อนไขผ่าน และเกณฑ์คะแนน
- เตรียม Recipe Rubric และชุดข้อมูลทดสอบสำหรับให้ AI ประเมิน
- ออกแบบหน้าผลประเมินและคำแนะนำที่ได้รับจาก AI
- ทำ Prefab สำหรับสถานะวัตถุดิบ เช่น ของชิ้นใหญ่ เปลี่ยนเป็นชิ้นที่หั่นแล้ว
- ทดสอบกรณีทำผิด เช่น หยิบผิด ลืมขั้นตอน ใส่ของผิดลำดับ หรืออาหารไหม้
- ส่ง Prefab และระบบย่อยที่ทดสอบแล้วให้ฝั่ง Mac M5 นำไปรวม

### วิธีทำงานของ Mac M1 และการส่งต่อให้ Mac M5

Mac M1 ใช้ `Assets/Scenes/GameplayTest_M1.unity` เป็นฉากทดลอง โดยฉากนี้เป็นสำเนาที่เริ่มจาก `MainVR` จึงมี XR Rig และ Environment ล่าสุดสำหรับทดสอบ แต่ Mac M1 สามารถเพิ่ม แก้ หรือลองระบบ Gameplay ได้โดยไม่ต้องแก้ `MainVR.unity` พร้อมกับ Mac M5

ชิ้นงานที่ต้องนำไปใช้จริงให้เก็บแยกไว้ใต้ `Assets/Gameplay` ตัวอย่างโครงสร้างคือ:

```text
Assets/Gameplay
├── Prefabs
│   ├── Ingredients
│   ├── Equipment
│   └── Zones
├── Scripts
└── UI
```

- `GameplayTest_M1` ใช้ประกอบและทดสอบระบบย่อย เช่น หยิบกะเพราแล้วนำไปวางใน Collection Zone
- `Prefabs` เก็บแม่แบบวัตถุที่นำไปวางซ้ำหรือใช้ใน Scene อื่นได้
- `Scripts` เก็บระบบและกฎการทำงานที่ผ่านการทดสอบ
- `UI` เก็บหน้าจอหรือองค์ประกอบ UI ที่ M5 นำไปเชื่อมกับฉากหลัก
- การแยกโฟลเดอร์ช่วยจัดงานให้หาและส่งต่อง่าย แต่ไม่ได้ป้องกัน Scene ถูกทับโดยอัตโนมัติ การป้องกันหลักคือไม่ให้ M1 และ M5 แก้ `MainVR.unity` พร้อมกัน

ภายใน Hierarchy ของ `GameplayTest_M1` ให้แยกวัตถุตามหน้าที่ดังนี้:

```text
Environment
├── Ground
├── ThaiHouse
├── GardenArea_Blockout
└── GardenPath_Blockout

GameplaySystems
├── CollectionZone_Krapow
├── IngredientManager
├── ObjectiveManager
└── ScoreManager
```

- `Environment` เก็บวัตถุและพื้นที่ที่มองเห็นในฉาก เช่น บ้าน สวน ทางเดิน และพื้น
- `GameplaySystems` เป็น Empty GameObject สำหรับจัดกลุ่มจุดตรวจและระบบที่ควบคุม Gameplay จึงไม่จำเป็นต้องมี Mesh หรือปรากฏเป็นวัตถุในเกม
- ตั้ง Transform ของ `GameplaySystems` เป็น Position `(0, 0, 0)`, Rotation `(0, 0, 0)` และ Scale `(1, 1, 1)` เพื่อให้วัตถุลูกใช้พิกัดตรงและย้ายระบบไป Scene อื่นได้ง่าย
- Collection Zone และ Manager อยู่ใต้ `GameplaySystems` ส่วนสวนและทางเดินอยู่ใต้ `Environment`

คำแปลชื่อที่ใช้ในงาน M1:

| ชื่อใน Unity | ความหมายภาษาไทย |
|---|---|
| `GameplayTest_M1` | ฉากทดสอบระบบ Gameplay ของ Mac M1 |
| `GameplaySystems` | กลุ่มสำหรับเก็บระบบการเล่นและจุดตรวจ |
| `GardenArea_Blockout` | แปลงสวนแบบจำลองหยาบ |
| `GardenPath_Blockout` | ทางเดินไปสวนแบบจำลองหยาบ |
| `CollectionZone_Krapow` | จุดรับและตรวจจับกะเพรา |
| `Krapow` | วัตถุดิบกะเพรา |

### Flow ปัจจุบันสำหรับอธิบายอาจารย์

Mac M1 ใช้ฉากแยกเพื่อทดลองระบบย่อยให้ทำงานครบก่อนส่งชิ้นงานที่ผ่านแล้วให้ Mac M5 นำไปเชื่อมในฉากหลัก:

```text
GameplayTest_M1
→ ผู้เล่นเดินจากบ้านไปสวน
→ ทดลองหยิบ Krapow
→ นำ Krapow กลับไปยังครัว
→ ทดลองวางใน Collection Zone
→ IngredientCollector ตรวจว่าเป็นวัตถุดิบชนิดที่กำหนด
→ ระบบแจ้งผลผ่านหรือแจ้งว่าเป็นวัตถุดิบผิดชนิด
```

ไฟล์ของระบบนี้จัดเก็บดังนี้:

```text
Assets/Gameplay
├── Prefabs/Ingredients/Krapow.prefab
├── Prefabs/Zones/CollectionZone_Krapow.prefab
├── Scripts/IngredientCollector.cs
├── Scripts/CollectionFeedbackUI.cs
└── UI/Fonts/Sarabun-Regular SDF.asset
```

สถานะปัจจุบัน:

- `GameplayTest_M1` สร้างแล้วและใช้ทดสอบโดยไม่แก้ `MainVR`
- `Krapow.prefab` สร้างแล้ว และทดสอบ Grab/Drop กับพื้นผ่าน
- `GardenArea_Blockout` และ `GardenPath_Blockout` สร้างแล้ว และทดสอบการเดินไปสวนผ่าน
- `CollectionZone_Krapow.prefab` และ `IngredientCollector.cs` สร้างแล้ว

## 7. การใช้ AI ในโปรเจกต์

AI เหมาะกับการวิเคราะห์ข้อมูลการเล่นและอธิบายว่าผู้เล่นทำถูกหรือผิดอย่างไร แต่ไม่ควรให้ AI เดาจากภาพในแว่นหรือเป็นผู้คำนวณคะแนนทั้งหมดเพียงลำพัง

ระบบประเมินควรเป็นแบบผสม:

```text
ผู้เล่นทำกิจกรรมใน Unity
→ Unity บันทึก Action Log
→ Rule-based System ตรวจข้อเท็จจริงและคำนวณคะแนนพื้นฐาน
→ AI วิเคราะห์ลำดับและข้อผิดพลาด
→ AI สร้างคำอธิบายและคำแนะนำเฉพาะผู้เล่น
→ แสดงผลหลังจบ Training หรือ Challenge
```

### ข้อมูลที่ Unity ต้องบันทึก

- วัตถุดิบที่หยิบและจำนวน
- ขั้นตอนที่ทำและลำดับเวลา
- การล้างและการหั่น
- ขนาดหรือจำนวนชิ้นหลังหั่น
- เครื่องปรุงที่ใส่และลำดับ
- ระดับไฟและระยะเวลา
- ระยะเวลาการปรุงและจำนวนการคน
- สถานะอาหาร เช่น ดิบ สุก หรือไหม้
- การปิดเตา การจัดจาน และการเสิร์ฟ

### สิ่งที่ระบบกฎตรวจ

- ใช้วัตถุดิบถูกชนิดและครบจำนวนหรือไม่
- ข้ามขั้นตอนหรือทำผิดลำดับหรือไม่
- ใช้ระดับไฟและเวลาตามเกณฑ์หรือไม่
- อาหารอยู่ในสถานะที่เสิร์ฟได้หรือไม่
- คะแนนพื้นฐานตาม Recipe Rubric

### สิ่งที่ AI ช่วยตรวจและอธิบาย

- สรุปข้อผิดพลาดหลายเหตุการณ์ให้เข้าใจง่าย
- วิเคราะห์ว่าผู้เล่นน่าจะสับสนในขั้นตอนใด
- สร้าง Feedback เฉพาะบุคคลหลังจบ Challenge
- แนะนำว่าควรกลับไปฝึกขั้นตอนไหน
- เลือกคำใบ้ที่เหมาะสมใน Training โดยอ้างอิงจากสิ่งที่ผู้เล่นทำผิด
- ในภาคเรียนที่ 2 สามารถสรุปแนวโน้มข้อผิดพลาดเพื่อแสดงใน WebBoard ของอาจารย์

ตัวอย่างผลจาก AI:

```text
ผู้เล่นเตรียมวัตถุดิบครบ แต่ใส่ใบกะเพราก่อนที่ไก่จะสุก
และใช้ไฟแรงนานเกินเกณฑ์ ควรฝึกการควบคุมระดับไฟและ
ตรวจสถานะของไก่ก่อนใส่ใบกะเพรา
```

AI ต้องได้รับเฉพาะข้อมูลเหตุการณ์ที่ Unity ตรวจจับได้จริง พร้อมสูตรและเกณฑ์มาตรฐาน เพื่อไม่ให้สร้างผลประเมินจากการคาดเดา หาก AI ใช้งานไม่ได้ ระบบกฎยังต้องสามารถคำนวณคะแนนและจบภารกิจได้ตามปกติ

### เป้าหมาย AI สำหรับภาคเรียนนี้

ทำต้นแบบกับหนึ่งเมนู โดยให้ Unity ส่ง Action Log และ Recipe Rubric ไปประเมิน แล้วรับผลกลับมาในรูปแบบข้อมูลที่แน่นอน เช่น คะแนน รายการข้อผิดพลาด และคำแนะนำ ระบบ AI ไม่จำเป็นต้องวิเคราะห์ภาพหรือวิดีโอจากแว่นในระยะแรก
