# Cookverse Thai — Project Context

อัปเดต: 22 ตุลาคม 2026

เอกสารนี้เป็นข้อมูลอ้างอิงหลักของโปรเจกต์ หากข้อมูลในบทสนทนาหรือเอกสารอื่นขัดกับเอกสารนี้ ให้ยึดเอกสารนี้ก่อน

> **ชื่อโปรเจกต์:** ใช้ชื่อ **Cookverse Thai** ในเอกสาร งานนำเสนอ และ GitHub ส่วนโฟลเดอร์ Unity บนเครื่องยังชื่อ `SiamCulinaryXR` ตามเดิม (ไม่เปลี่ยนเพื่อไม่ให้ Path และ Library ของ Unity เสีย)

## 1. แนวทางหลัก

Cookverse Thai เป็นระบบจำลองการเรียนรู้การทำอาหารไทยผ่านแว่น VR พัฒนาด้วย Unity XR ผู้เล่นได้ลงมือทำจริงในโลกเสมือน ตั้งแต่รับภารกิจ เก็บวัตถุดิบ เตรียม ปรุง จัดจาน เสิร์ฟ และรับผลประเมิน

เมนูต้นแบบคือ **ผัดกะเพราไก่** ผู้สอนในเกมคือ **ป้าแสง** เจ้าของบ้าน รายละเอียดเนื้อหาอยู่ที่ [`GAMEPLAY_CONTENT_V1.md`](../Planning/Gameplay/GAMEPLAY_CONTENT_V1.md)

## 2. ขอบเขตตามคำแนะนำของอาจารย์

```text
ภาคเรียนนี้ (ถึง 30 พ.ย.): Unity XR/VR + Gameplay Systems + WebXR
ภาคเรียนที่ 2 (ม.ค.):     WebBoard + Visual Polish + Content Polish
```

### ภาคเรียนนี้

ทำระบบตั้งแต่ต้นจนจบให้เล่นได้จริงก่อน โดยใช้โมเดลทรงง่าย (Blockout) ได้ สิ่งสำคัญคือระบบต้องตรวจจับการหยิบ วาง หั่น เปลี่ยนสถานะ และลำดับการทำงานได้ถูกต้อง

- การเคลื่อนที่และการควบคุมใน XR
- การหยิบ วาง ปล่อย และใช้งานวัตถุ
- การรับภารกิจและแสดงเป้าหมาย
- การเก็บวัตถุดิบจากสวน ตู้เย็น และตะกร้า
- การล้างและหั่นวัตถุดิบ
- เตาแก๊สแบบปุ่มบิด 3 ระดับ กระทะ เวลา และสถานะอาหาร (ดิบ กำลังสุก สุก ไหม้)
- การใส่วัตถุดิบและเครื่องปรุงตามลำดับ
- การจัดจาน จุดเสิร์ฟ และจบภารกิจ
- Training Mode และ Challenge Mode
- การคำนวณคะแนนตามกฎและแสดงข้อผิดพลาด
- Action Log สำหรับระบบกฎและ AI
- AI วิเคราะห์ผลและให้คำแนะนำหลังจบภารกิจ
- Build และทดลองใช้งานผ่าน WebXR
- ทดสอบบนแว่น Meta Quest 3 จริง

### ภาคเรียนที่ 2

- WebBoard สำหรับอาจารย์และผู้ดูแลระบบ
- ปรับโมเดล วัตถุดิบ บ้าน สวน และครัวให้สวยงาม
- Material, Texture, แสง, Animation และเสียง
- ปรับ UI และประสบการณ์ใช้งาน

การเปลี่ยนทรงง่ายเป็นโมเดลจริงต้องทำผ่าน Prefab โดยรักษา Collider จุดจับ และ Component เดิมไว้ เพื่อไม่ต้องรื้อระบบ

## 3. Gameplay Flow หลัก

```text
เริ่มเกม → เลือก Training หรือ Challenge
→ คุยกับป้าแสงเพื่อรับภารกิจ
→ ไปสวน เก็บกะเพราและพริก
→ กลับครัว หยิบไก่จากตู้เย็นและกระเทียมจากตะกร้า
→ ล้างผัก → หั่นไก่ พริก กระเทียม
→ บิดเปิดเตา ปรุงตามลำดับ
→ ตักใส่จาน → วางที่จุดเสิร์ฟ
→ กลับไปหาป้าแสง → แสดงคะแนนและข้อผิดพลาด
```

## 6. สถานะปัจจุบัน (22 ต.ค. 2026)

ผลทั้งหมดด้านล่างทดสอบใน **Unity Editor + XR Interaction Simulator** เท่านั้น ยังไม่มีผลจากแว่นจริงหรือ WebXR

### เสร็จแล้ว

- **XR Foundation:** เดิน หมุน Teleport หยิบ วาง โยน และ Collider ผนัง
- **ฉาก `MainVR`:** บ้านเรือนไทย หลังคา บันได ชาน สวน และครัวแบบ Blockout ครบทุกโซน (วัตถุดิบ ล้าง เตรียม ปรุง จัดจาน จุดจบภารกิจ) พร้อมตำแหน่ง NPC และจุดเกิดผู้เล่น
- **ภารกิจ:** เริ่มรอบ → เดินเข้าโซนป้าแสง → รับภารกิจ → ขั้น `collect_garden`
- **เก็บวัตถุดิบ:** ใบกะเพรา 1 กำ และพริก 3 เม็ด ตรวจชนิด กันการนับซ้ำ แยกกรณีผิดชนิดหรือผิดขั้น และรีเซ็ตได้
- **UI ภาษาไทย:** ข้อความผลการวางวัตถุดิบ และรายการเช็กลิสต์ภารกิจ
- **มือ VR:** โมเดลมือที่ทำเองเชื่อมกับ XR Hands แล้ว (เห็นใน Simulator)

### ยังไม่ได้ทำ

- ตู้เย็น ล้าง หั่น เตา กระทะ ความสุก จัดจาน เสิร์ฟ
- Action Log, การคำนวณคะแนน, Result UI
- Training / Challenge Mode
- AI, WebXR และการทดสอบบน Quest 3 (นัดทดสอบแว่น **27 ต.ค. 2026**)

แผนงานที่เหลือดูที่ [`PLAN_Oct-Nov_2026.md`](../Planning/Schedule/PLAN_Oct-Nov_2026.md)

## 7. การใช้ AI ในโปรเจกต์

AI ช่วยอธิบายผลและให้คำแนะนำ แต่ **ไม่เป็นผู้ตัดสินคะแนนหรือการผ่านภารกิจ** ระบบกฎใน Unity เป็นผู้ตัดสินเสมอ

```text
ผู้เล่นทำกิจกรรม → Unity บันทึก Action Log
→ ระบบกฎตรวจข้อเท็จจริงและคำนวณคะแนน
→ AI อ่าน Log + คะแนน แล้วอธิบายข้อผิดพลาดและให้คำแนะนำ
→ แสดงผลหลังจบภารกิจ
```

ตัวอย่างผลจาก AI:

```text
ผู้เล่นเตรียมวัตถุดิบครบ แต่ใส่ใบกะเพราก่อนที่ไก่จะสุก
และใช้ไฟแรงนานเกินเกณฑ์ ควรฝึกการควบคุมระดับไฟและ
ตรวจสถานะของไก่ก่อนใส่ใบกะเพรา
```

### ข้อตกลงเรื่องป้าแสง AI (16 ต.ค. 2026)

- ทำวงจรเล่นหลักให้จบก่อน แล้วจึงเพิ่มการพิมพ์คุยกับป้าแสง เสียงพูดและไมโครโฟนเป็นขั้นถัดไป
- ป้าแสง AI ทักทาย อธิบาย และให้คำใบ้ เช่น "ต้องไปไหนต่อ" หรือ "ทำไมของชิ้นนี้ไม่ถูก" โดยรับสถานะปัจจุบันจากระบบเกม
- `ObjectiveManager` และระบบกฎเป็นผู้ตัดสินจำนวน ความถูกต้อง การผ่านภารกิจ และคะแนน AI แก้ค่าเหล่านี้ไม่ได้
- ต้องมีข้อความสำรองเมื่อ AI ใช้งานไม่ได้ เกมต้องเล่นจบได้เสมอ

### ข้อกำหนดข้อมูล

- AI ได้รับเฉพาะเหตุการณ์ที่ Unity ตรวจจับได้จริง พร้อมสูตรและ Rubric
- ไม่ฝัง API Key ไว้ใน Unity ให้เรียกผ่านบริการกลาง
- ระยะแรกไม่ใช้ AI วิเคราะห์ภาพหรือวิดีโอจากแว่น

## 8. หลักตัดสินใจ

1. **ระบบใช้งานได้จริงก่อนความสวยงาม** โมเดลเปลี่ยนได้ในเดือนมกราคม
2. **ผลบน Simulator ไม่เท่ากับผลบนแว่นจริง** และผลบน APK ไม่เท่ากับผลบน WebXR ต้องบันทึกแยกกันเสมอ
3. **ลดความซับซ้อนของท่าทางได้ แต่ต้องคงกฎการเรียนรู้** เช่น หั่นด้วยการแตะมีด 3 ครั้งได้ แต่ระบบยังต้องรู้ว่าหั่นแล้วหรือยัง
4. **สูตร จำนวน และ Rubric เป็นฉบับต้นแบบ** ต้องให้อาจารย์ยืนยันก่อนล็อก

## 9. เรื่องที่ยังต้องยืนยัน

- **เมนูต้นแบบ:** เอกสารเนื้อหา ภาพแปลน v5 และบทพูดป้าแสงใช้ **ผัดกะเพราไก่** แต่แผนครัวฉบับ 1 ต.ค. เคยเขียนเป็นผัดกะเพราหมู เอกสารชุดนี้ใช้ **ไก่** เป็นหลัก
- สูตร จำนวนวัตถุดิบ ค่าความร้อนของเตา และ Rubric v1 ต้องให้อาจารย์ยืนยัน
- บริการ AI ที่จะใช้และสิทธิ์การใช้งาน ต้องพร้อมภายในต้น พ.ย.
